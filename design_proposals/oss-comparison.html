一句话结论

研究层 · 别人已蹚路

多 agent 决策、新闻分析、宏观数据、情绪建模——TradingAgents（9.5 万星）等已验证成熟方案，直接抄设计省几个月踩坑。

执行层 · 我们的壁垒

代码级风控、真实成交闭环、审计溯源——开源项目普遍只有模拟交易和 LLM 辩论式风控，挂真实资金的工程能力是稀缺品。

数据层 · 可借架构

OpenBB（7.1 万星）的 Provider 模式、FRED 序列接口、预测市场概率——数据接入方式可以按他们的模式搭。

分层定位：谁在哪个层面

交易系统分三层，开源项目集中在研究层和数据层，我们集中在执行层——重叠区只有"新闻/宏观集成"。

研究层 · 决策与信息处理

多 agent 编排、新闻/情绪/宏观分析、报告生成、决策推理。这是开源最拥挤的地方：TradingAgents、FinGPT、FinRobot、FinRL、Trading-R1 都在这一层。

策略：借鉴 TradingAgents 的"按需查询 + 分析师报告 + 情绪独立建模"

数据层 · 数据接入与聚合

行情、新闻、宏观指标、预测市场数据的统一接入。OpenBB 是标杆（Provider 抽象、多源路由）。

策略：复用 OpenBB 式 Provider 接口 + FRED 式历史序列 + Polymarket 概率

执行层 · 下单与资金安全

交易所接入、订单管理、成交对账、风控引擎、审计、监控、通知。freqtrade/Hummingbot 有执行工程但无 LLM 决策；TradingAgents 有 LLM 决策但只有模拟盘。

我们独有：代码风控 + 真实成交闭环 + 审计 —— 没人同时具备

借鉴清单

哪些直接抄、哪些守住——按上两轮的源码级调研结论。

📦 直接借鉴（开源已验证）

  • 新闻按需查询而非预注入：决策链中工具化检索，查当下数据 ← TradingAgents
  • 分析师产出结构化报告：报告传下游，原始文本不进决策上下文 ← TradingAgents
  • 宏观历史序列接口：CPI/利率/美债按时间窗口拉序列 ← FRED 模式
  • 预测市场概率当前置信号：加息概率/衰退概率做成指标 ← Polymarket
  • 情绪与新闻分开建模：资金费率/多空比独立成信号 ← Sentiment Analyst
  • 防未来泄漏纪律：半开时间窗口 + UTC 归一化，为回测留安全线 ← test_news_lookahead
  • Provider 数据接入抽象：多源统一接口、可替换 ← OpenBB

🛡 守住壁垒（开源没有的）

  • 纯代码 RiskEngine：下单/改单必经引擎，LLM 只建议不执行——开源都是 LLM 辩论式"软风控"
  • 成交落库与对账：私有 WS 成交订阅 + 回填对账，挂真钱的必备闭环
  • 统一审计溯源：LLM 工具调用全记录，密钥永不出 .env
  • testnet/live 双模式：沙盒实测字段再上生产，Gate 参数禁止猜测
  • 24h 连续运行工程：调度、监控 API、前端、Telegram 通知——开源框架跑研究跑批，我们常驻服务
行动结论：研究层和数据层"抄作业"（TradingAgents 的新闻/宏观设计 + OpenBB 的 Provider 模式，已融入前两份设计稿）；执行层继续自建不外包——这一层开源项目的深度都不够挂真实资金。
