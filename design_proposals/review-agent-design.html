系统全景：复盘子系统住在哪

所有新组件都在现有 bootstrap 单进程内，紫色为新增。复盘 agent 通过只读工具主动下钻交易与决策数据，唯一写出口是 submit_strategy_revision —— 它依然碰不到交易。

交易决策域（现有，不动）

DecisionLoopLLM 决策循环
ToolRegistry → RiskEngine受控交易工具 + 硬风控
Gatewaypaper / testnet / live
PromptLoader读 system_prompt.md，mtime 热重载

复盘子系统（新增 src/review/）

ReviewScheduler每日定时 + 手动触发 + 防重入锁
ReviewAgent独立 review_prompt.md · 复用 LLMProvider · 多轮工具调用循环
ReviewToolRegistry7 个只读工具 + 1 个写工具，独立注册表，与交易工具零交集
StrategyStore策略版本管理 · 写前校验 · 原子写回 · 回滚
ReviewPromptLoader复盘专用 system prompt，与策略书分离

数据与出口

Repo（只读）trades / decisions / audit 查询
AuditTrail复盘轮与工具调用统一审计（wake_source=review）
SQLite 两张新表review_reports + strategy_versions
system_prompt.md被原子写回 → 下轮决策自动生效
Notifier / 前端摘要推送 · 版本 diff · 回滚 · 报告
隔离边界：ReviewToolRegistry 里没有任何交易工具（无 place_order / amend_order / cancel_order）， 也不持有 Gateway 引用。7 个只读工具只经 Repo 查询；唯一写工具 submit_strategy_revision 也不直接写文件—— 它把修订请求交给 StrategyStore，先过代码校验才落盘。复盘 agent 想影响系统，只有这一条受控通道。
读取流向：LLM ⇄ ReviewTools → Repo / AuditTrail 修订流向：LLM → submit_strategy_revision → StrategyStore → system_prompt.md 生效流向：PromptLoader 检测 mtime → 下轮决策用新策略

复盘工具集（正式清单）

7 个只读工具让复盘 agent 按需下钻：从统计概况 → 决策轮列表 → 单轮决策原文 / 工具调用链 / 上下文快照。1 个写工具提交策略修订。schema 与审计机制复用现有 ToolSpec / AuditTrail 模式。

get_review_stats只读

复盘统计：按时间范围、按策略版本统计胜率 / 盈亏 / 盈亏比等——回答「v3 这版策略到底赚不赚钱」。

参数说明
start_ts / end_ts 必填统计区间（Unix 秒）
strategy_md5按策略版本过滤（可空=全部）
contract按合约过滤（可空）

返回：平仓笔数、总盈亏、胜率、盈亏比、平均盈/亏、最大单笔亏损、各合约分布。全部代码计算（Decimal），LLM 只看不算。统计样本 = 有 pnl 记录的平仓成交。

list_decision_rounds只读

决策轮列表：先浏览再下钻的入口。

参数说明
start_ts / end_ts 必填时间范围
strategy_md5按策略版本过滤（可空）
limit默认 20，上限 100

返回：round_id、wake_source(唤醒来源)、strategy_md5(策略版本摘要)、一行摘要、error(是否报错)、时间。

get_decision_detail只读

读取某轮 LLM 的决策内容：它当时想了什么、最终输出了什么。

参数说明
round_id 必填决策轮标识
max_charsllm_raw 截断上限，默认 4000

返回：决策摘要 + llm_raw(LLM 原始输出) + wake_source + strategy_md5 + 时间。

get_tool_call_chain只读

读取某轮的完整工具调用链：它调了什么、风控放行还是拒绝、结果如何。

参数说明
round_id 必填决策轮标识

返回：按 seq(调用序号) 排序的链：tool、args_json(入参)、risk_verdict(风控结论)、risk_reason(风控理由)、result 摘要、duration_ms(耗时)。

list_trades只读

成交明细查询：逐笔看盈亏与来源。

参数说明
start_ts / end_ts 必填时间范围
contract / source按合约 / 按来源过滤（可空）
limit默认 50，上限 200

返回：时间、合约、size(带方向张数)、price、fee(手续费)、pnl(已实现盈亏)、source(成交来源)、round_id。

get_round_context只读

读取某轮决策时的市场与账户快照：当时看到了什么行情、持什么仓。

参数说明
round_id 必填决策轮标识
max_chars快照截断上限，默认 4000

返回：audit_rounds.context_snapshot(决策上下文快照)，含当时行情/持仓/笔记/近期成交。

get_strategy_versions只读

查看策略当前全文与历史版本：现在策略长什么样、以前改过什么。

参数说明
version_id可空：空=版本列表+当前全文；指定=该版本全文

返回：版本列表（vN、created_by(来源)、reason(修改理由)、md5、时间）或指定版本全文。

submit_strategy_revision写 · 唯一出口

提交策略修订：唯一允许改变系统状态的工具。不直接写文件，交给 StrategyStore 校验后生效。

参数说明
new_prompt_md 必填策略书完整新文本（全文重写）
reason 必填修改理由（写入版本记录）

返回：通过 → 新版本号 vN + md5；拒绝 → 校验失败原因列表（原文件不动）。

3

每日复盘流程（点击步进 / 自动播放）

LLM 自主决定查什么：通常先统计概况，再对可疑的亏损轮次下钻决策原文与工具链。最多 12 轮工具调用。

4

输出与修订协议：结构化由工具 schema 保证

工具化之后不再要求 LLM 手写 JSON——参数校验由工具框架做，比 prompt 约束可靠一个量级。

复盘报告 = 最终文本

工具调用循环结束后，LLM 的最后一段文本输出即 report_md(复盘报告正文)，由 ReviewAgent 直接落库。无需任何解析，天然健壮。

策略修订 = 工具调用

LLM 认为需要改策略时，调用 submit_strategy_revision；认为无需调整时不调即可——「不改」是不需要任何输出的默认状态，避免为改而改。

为什么全文重写

策略书很短（模板仅 27 行），new_prompt_md 传完整新文本对 LLM 最可靠；版本 diff 由服务端生成、前端着色展示。

5

策略版本链：改了什么、哪轮决策用了哪版，全部可查

每次修改（人改 / 复盘 agent 改 / 回滚）都追加一个版本，历史永不篡改。点击下方按钮演示「复盘改写」和「一键回滚」。

版本 ↔ 决策轮怎么关联？

现有 audit_rounds.prompt_md5 是「策略书 + 工具说明段」拼装后的 md5（src/agent/prompts.py:36-40），无法直接对上版本表。

处理：PromptLoader 增加返回策略书原文 md5，audit_rounds 和 decisions 各幂等迁移加一列 strategy_md5(策略书原文摘要)。前端按它 join 版本表，每轮决策显示 「策略 v12 · review_agent」。这也是 get_review_stats 能按策略版本统计胜率的基础。

生效与回滚机制

  • 生效：StrategyStore 校验 → 临时文件 → 原子替换 system_prompt.md → 落版本。PromptLoader 靠 mtime 热重载，下一轮决策自动用新版，零改动复用。
  • 回滚：把目标版本 content 写回文件 + 追加一条 created_by='rollback' 的新版本——回滚本身也留痕。
  • 人改也算数：前端/API 人工改策略同样走 StrategyStore，记 created_by='human'，版本链覆盖所有修改入口。
6

模块拆分：新增 src/review/，七个小文件

遵守项目 ≤300 行/文件、单一职责的硬性规范；工具层与交易 agent 的工具层平行，互不 import。

models.py

ReviewReport(复盘报告)、StrategyVersion(策略版本) 两个 pydantic 模型。

prompts.py

ReviewPromptLoader：加载 review_prompt.md，mtime 热重载，与交易策略书完全分离。

agent.py

ReviewAgent.run()：创建审计轮 → 多轮工具调用循环（≤12 轮）→ 落报告 → 推送摘要。

tool_schemas.py

8 个工具的 ToolSpec 定义（名称/描述/JSON schema），与交易工具平行独立。

tool_handlers.py

ReviewToolRegistry：7 个只读 handler 经 Repo/AuditTrail 查询 + 截断控制；submit 交 StrategyStore。

strategy.py

StrategyStore：版本表读写、写前校验、原子写回 system_prompt.md、回滚。人和 agent 改策略的统一入口。

scheduler.py

ReviewScheduler：每分钟巡检到点触发（参照 bootstrap._funding_loop 模式）+ run_now() 手动入口 + asyncio.Lock 防重入。

7

安全不变量：代码强制，不靠 LLM 自觉

自进化最大的风险是「改坏策略」与「越权操作」。四条不变量全部落在代码里，并有对应测试。

1工具面物理隔离

ReviewToolRegistry 中没有任何交易工具、不持有 Gateway 引用。复盘 agent 碰不到下单、撤单、改单——不是被风控拦住，而是工具根本不在它手里。

2写前校验

submit_strategy_revision 不直接写文件。StrategyStore 校验：非空（≥100 字符）、≤32KB、与当前版本有实际差异；任一不过则拒绝，原文件不动。

3失败不扩散

LLM 异常 / 工具异常 / 校验拒绝 → 只落 error 记录 + Telegram 告警。交易决策循环零感知，两系统无共享可变状态。

4统一审计 + 密钥边界

复盘轮与全部工具调用经 AuditTrail 落库（wake_source=review），满足「LLM 工具调用须进统一审计」；只读工具只查业务数据，不接触 .env，契约测试密钥扫描覆盖新端点。

8

数据模型：两张新表 + 两个迁移列

全部经 src/memory/db.py 幂等迁移加入，业务层只经 Repo 访问，不直接写 SQL。

strategy_versions(策略版本表)

id            INTEGER PK
content       TEXT    -- 策略书全文
md5           TEXT    -- 原文摘要
created_by    TEXT    -- human / review_agent / rollback
reason        TEXT    -- 修改理由
report_id     INTEGER NULL  -- 关联复盘报告
created_at    INTEGER

review_reports(复盘报告表)

id               INTEGER PK
period_start     INTEGER -- 复盘区间起
period_end       INTEGER -- 复盘区间止
stats_json       TEXT    -- 统计指标(代码计算)
report_md        TEXT    -- 报告正文
strategy_action  TEXT    -- none / rewrite
new_version_id   INTEGER NULL -- 产生的新版本
error            TEXT NULL
created_at       INTEGER

迁移列：audit_rounds 与 decisions 各加 strategy_md5(策略书原文摘要)，沿用 db.py 现有 PRAGMA table_info + 幂等 ALTER 机制。get_review_stats 按此列把成交 join 到策略版本。

API 与前端：复用现有模式，零新 npm 依赖

新端点同步进 tests/test_contract.py 契约测试 + web/src/api/types.ts / http.ts 适配层。

新增端点

方法路径说明

GET/api/review/reports/{id}报告详情

前端三处改动

  • 策略编辑页加版本历史侧栏：版本列表（vN · 来源 · 理由 · 时间）、点击看 diff（行首 +/- 着色，<pre> 展示）、回滚按钮。
  • ConsolePage 新增复盘报告面板：列表 + 详情（含该轮复盘的工具调用链，复用现有轮详情样式），报告正文 whitespace-pre-wrap 展示——不引 markdown 库。
  • 决策轮时间线加版本标签：每轮显示「策略 vN · 来源」，点击跳转该版本。

一期明确不做（YAGNI 边界）

  • ✕不回捞历史 K 线喂给复盘 LLM——决策轮上下文快照已含当时行情，Gateway.get_candlesticks 能力留待二期。
  • ✕不做周报/月报聚合、不做单笔即时复盘——先跑通每日闭环。
  • ✕不做复盘独立模型配置、不做多策略 A/B——复用现有 provider。
  • ✕不给复盘 agent 任何交易/调度/笔记写工具——write_note、set_next_wakeup 等不在其工具面内。
