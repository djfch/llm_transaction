## 一、结论摘要

本次改动的单元测试与静态检查均通过，但真实前后端组合存在契约断裂：默认 `1h(一小时周期)` 页面会因 `limit(返回根数)` 超过后端上限而直接返回 422；修复该问题后，`scalar(标量指标)` 仍不会被真实请求，因此 `atr14(平均真实波幅)`、`vol_ratio(量比)`、`oi(持仓量)` 会长期显示“无数据”。

## 二、问题清单

### 1. [P1] 默认指标请求会被后端以 422 拒绝

**位置**

- `src/server/routes_indicators.py:88`
- `web/src/components/console/KlinePanel.tsx:41`
- `web/src/components/console/KlinePanel.tsx:112`

**现象**

默认周期为 `1h(一小时周期)`，前端请求 `limit(返回根数)=200`；`15m(十五分钟周期)` 请求 700，但后端路由限制最大值为 100。

```text
打开默认 K 线页
  → 前端请求 /api/indicators/series?interval=1h&limit=200
  → FastAPI 参数校验要求 limit <= 100
  → 返回 HTTP 422
  → 指标图和徽标整体加载失败
```

**修复建议**

统一前后端上限，并与 `HISTORY_LIMIT(指标历史深度)` 的实际能力对齐。增加一条经过真实 FastAPI 路由的前后端契约测试，至少覆盖 1h、15m、4h、1d 四个页面周期。

### 2. [P2] 标量指标未进入真实请求

**位置**

- `web/src/hooks/useIndicatorSeries.ts:35`
- `web/src/hooks/useIndicatorSeries.ts:55-57`
- `src/market/indicators_setup.py:45-49`

**现象**

前端主动过滤全部 `scalar(标量指标)`，但后端只返回明确传入的 `keys(指标键)`，不会自动补齐短名单里的标量指标。

```text
shortlist(指标短名单) = [ema20, atr14, oi]
  → 前端请求 keys = [ema20]
  → 后端响应只有 ema20
  → atr14、oi 找不到响应条目
  → 徽标永久显示“无数据”
```

前端测试桩额外返回了未请求的标量指标，掩盖了真实契约问题。

**修复建议**

前端发送完整短名单，或由后端明确自动补齐当前短名单中的标量指标；随后增加真实路由级契约测试，禁止测试桩返回未请求的数据。

### 3. [P2] 合约切换失败时会残留上一合约指标

**位置**

- `web/src/hooks/useIndicatorSeries.ts:79-99`
- `web/src/hooks/useApiData.ts`

**现象**

`useApiData` 在依赖变化或新请求失败时不会清除旧 `data(响应数据)`；指标 Hook 也未校验响应中的 `contract(合约)` 和 `interval(周期)`。

BTC 切换到 ETH 后，如果 ETH 指标请求失败，旧 BTC 指标可能按相同 K 线时间戳继续挂在 ETH 图上，形成错误行情展示。

**修复建议**

只消费与当前合约、周期一致的响应；切换合约或周期时立即隔离旧指标数据，并补充“切换后请求失败”的回归测试。

### 4. [P2] 复盘 Agent 使用启动时的旧 watchlist

**位置**

- `src/review/agent.py:102`
- `src/server/routes_config.py:256-257`

**现象**

复盘 Agent 构造时把共享 `watchlist(合约白名单)` 复制为 `tuple(不可变快照)`；后续接口仅原地更新原列表，因此复盘 Agent 不会看到热更新结果。

- 新增合约仍会被复盘指标工具拒绝；
- 已删除合约仍可能被允许；
- 若启动时名单为空，后续可能一直不执行名单限制。

**修复建议**

保留共享列表引用，或注入实时读取回调，确保执行 Agent、复盘 Agent、服务端路由和 OI 缓存读取同一份当前名单。

### 5. [P2] 横盘行情被计算为 RSI=100

**位置**

- `src/market/indicators.py:49-52`

**现象**

当 `avg_gain(平均上涨)=0` 且 `avg_loss(平均下跌)=0` 时，当前逻辑仍返回 100。连续相同收盘价会因此被解释成极端超买，而实际行情没有方向。

**修复建议**

区分以下两种情况：

- 只有 `avg_loss(平均下跌)=0`：持续上涨，可返回 100；
- `avg_gain(平均上涨)` 与 `avg_loss(平均下跌)` 同时为 0：横盘，应返回中性值 50 或明确的无数据状态。

补充纯横盘、纯上涨、纯下跌三组回归测试。

### 6. [P2] 默认 paper 模式的持仓量永久无数据

**位置**

- `src/paper/engine.py:275-277`
- `src/bootstrap.py:116-123`

**现象**

默认指标短名单包含 `oi(持仓量)`。正常 paper 模式已经创建 Gate 公共 REST 网关获取真实合约和 K 线，但 `PaperGateway.fetch_open_interest()` 固定返回 `None`，导致执行 Agent 每轮只能得到“持仓量=无数据”。

Gate 官方 Futures statistics 接口可提供公开持仓量数据：[Gate API v4 Futures 文档](https://www.gate.com/docs/developers/apiv4/en/futures/)。

**修复建议**

将公共行情网关作为独立 OI 数据源注入指标子系统；只有纯离线 mock 场景才降级为 `None`，不要让模拟撮合网关承担公共市场数据职责。

### 7. [P3] 生产标签没有按项目规则归一化

**位置**

- `web/src/utils/indicatorSeries.ts:66`
- `src/market/indicator_service.py` 中 `REGISTRY(指标注册表)`
- `AGENTS.md:47`

**现象**

前端只按全角括号 `（` 切分，后端真实标签使用半角括号 `(`。生产环境会显示 `EMA20(指数均线)` 等混合标签，而前端测试使用全角括号假数据，因此没有发现问题。

这也违反项目的用户可见字段规则：当文本属于“英文键或枚举值 + 括号内中文释义”时，应只保留目标中文文本。

**修复建议**

统一后端标签格式，并让前端同时兼容半角、全角括号；按照 `AGENTS.md` 的字段标签规则输出最终展示文本，内部指标键保持不变。

## 四、为什么绿测仍不能提交

当前测试主要在各层内部自证：

- 路由测试明确限制 `limit(返回根数) <= 100`；
- Hook 测试却直接模拟客户端成功返回 `limit=200` 的结果；
- Hook 测试只请求非标量指标；
- mock 响应却额外返回未请求的标量指标；
- 前端标签测试使用全角括号；
- 后端真实标签使用半角括号。

这些测试分别都能通过，但组合起来并不代表真实系统可用。修复时应优先补一条贯穿“前端参数 → FastAPI 路由 → 指标服务 → 前端适配”的契约测试。
